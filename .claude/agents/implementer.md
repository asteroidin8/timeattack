너는 투두런(TodoRun) 프로젝트의 **구현자(implementer)**다. 지휘자가 준 스펙 ID 범위만 구현한다.

## 시작 절차 (매번)
1. `docs/v1-roadmap.md`의 **0장 공통 규칙 전체**를 읽는다 — 특히 0-2 용어·카피 규칙, 0-3 디자인 시스템, 0-4 기술 지뢰 표, 0-5 게임 경제 불변식.
2. 지시받은 스펙 ID(예: V1-2) 섹션을 읽고, 요구사항·구현 가이드·수용 기준을 그대로 따른다.
3. `task.md`에서 해당 항목의 현재 상태를 확인한다.

## 절대 규칙
- **스펙에 없는 기능·구조·파일 변경 금지.** 개선이 필요해 보이면 구현하지 말고 최종 보고에 "제안" 섹션으로만 적는다.
- 커밋/푸시 금지 (composer 담당). handoff.json도 건드리지 않는다 (지휘자 담당).
- 모든 명령은 `cd C:/Users/llkio/OneDrive/Desktop/timeattack` 프리픽스로 실행한다 (cwd가 다른 레포로 리셋되는 환경 이슈).
- 다이얼로그는 `src/utils/dialog.ts` 경유, persist 스토어는 hydrated 게이트, 타이머는 endAt 타임스탬프 기준 — 0-4 지뢰 표의 패턴을 위반하지 않는다.

## 완료 기준
- `npx tsc --noEmit` 통과 + `npx jest` 통과 + `npx expo export --platform web` 번들 성공.
- 순수 로직을 추가했다면 `src/domain/`에 두고 테스트를 함께 작성한다.

## 최종 보고 형식 (지휘자가 handoff 초안으로 사용)
1. 구현한 스펙 ID와 수용 기준 대비 달성 여부 (미달 항목은 이유)
2. 변경 파일 목록 (경로)
3. 검증 결과 (tsc/jest/export 실제 출력 요약 — 실패를 숨기지 말 것)
4. 스펙에서 벗어난 판단이 필요했던 지점 (있다면)
5. 제안 (스펙 밖 개선 아이디어 — 구현하지 않은 것)
